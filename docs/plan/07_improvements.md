# 改善案（Week 24 公開後）

Week 24 で公開した DaikoLink について、実際に代講を受ける側の経験から、より良くするための機能を3つ考えた。

## 1. 代講のリマインド通知

**課題**：代講を引き受けても、依頼が前すぎて当日忘れてしまうことがある（自分の経験から）。代講者が来なければ、結局スタッフが当日に電話で探すことになる。

**内容**：確定した代講について、前日の夜に代講者へメールでリマインドを送る。件名は「【明日の代講】11/8（土）5限」のように、通知を開かなくても日時が分かる形にする。前日の夜より後に確定した代講は、確定メールが届いているので送らない。

## 2. 依頼ごとの掲示板

**課題**：依頼文にすべてを書くのは手間がかかる。追加で聞きたいことは LINE で個別にやり取りしているため、やり取りが散らばって残らない。また、LINE を追加していない講師とはやり取りが難しい。

**内容**：依頼文には最低限だけを書き、聞きたいことが出たときに依頼ごとの掲示板でやり取りする。LINE を追加していなくても、サイト上でやり取りできる。見られるのは依頼者と応募者だけ。書き込みのたびにメールは送らず、依頼詳細と一覧に「新しいコメントあり」の印を出す。生徒の情報をどこまで書いてよいかは、試験運用の前に塾に確認する。それまでは名前を書かず、学習の内容（範囲・宿題・教材）だけにする。（要件定義書の US-11）

## 3. 見つからないときの一斉連絡

**課題**：依頼を出したときのメールは、その日に休みの先生には関係ないと思われて読み流されやすい。当日まで代講者が見つからないと、結局スタッフが電話で1人ずつ探すことになる。

**内容**：授業の当日の正午になっても代講者が決まっていない場合、その日に授業が入っていない先生へ「【至急】本日の代講者を探しています」というメールを一斉に送る。同じタイミングでスタッフにも未確定の依頼を知らせる（要件定義書の US-18）。休みの日に連絡が来るのが負担な先生もいるため、「急な代講の連絡を受け取る／受け取らない」を各自で選べるようにする。

## 優先順位

1と3を優先して実装する。

特に優先度が高いのは3。DaikoLink は、代講者が見つからずにスタッフの業務が増えることを防ぐために作った。代講者を探す手間をなくすという目的に最も直結するのが3である。

1も同じくらい優先する。せっかく代講者が決まっても、当日に来なければもう一度探すことになり、3と同じ問題が起きてしまうからである。

2は、あると便利だが、絶対に必要というわけではない。業務の多くはマニュアル化されており、知りたいことがあっても授業で困ることはほとんどないからである。ただし、生徒の中には繊細な子もいるため、そうした生徒への配慮を考えると必要になる場面もある。そのため、1と3のあとに実装する。

## 実装（1と3）

| 項目 | 内容 |
|---|---|
| 送る時刻 | リマインド：前日の 20:00 ／ 一斉連絡：当日の 12:00（スケジューラー。本番は cron で毎分 `schedule:run`） |
| リマインドの送り先 | 明日の代講が確定している代講者だけ。同じ日に複数あるときは1通にまとめ、件名は「ほか1件」とする |
| 一斉連絡の送り先 | 当日に授業が入っていない、在籍中の講師のうち「急な代講の連絡を受け取る」にしている人。あわせて全スタッフに未確定の一覧を送る |
| 対象外 | 授業がすでに始まった依頼・確定済み・取り消し済みの依頼 |
| 二重送信の防止 | 依頼ごとに `reminded_at`・`urgent_notified_at` を記録し、送ったものには二度送らない |
| 受け取らない設定 | プロフィールの「通知の設定」で講師本人が切り替える（最初は全員が受け取る）。リマインドはこの設定に関係なく届く |
