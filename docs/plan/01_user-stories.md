# ユーザーストーリーの優先順位付け（プロダクトバックログ）

## 優先順位の決め方
1. **MoSCoW**：要件定義書 v1.2（メンターレビュー後）の Must / Should / Could をそのまま使う
2. **Must の中の順番**：コアバリュー「急な欠勤でも、講師どうしがサイト上で代講者を見つけて確定できる」の流れ（シフトを見る → 依頼 → 応募 → 確定）に沿って、**前の機能がないと作れないもの**から並べる
3. **ストーリーポイント（SP）**：Week 19 の工数見積もりに合わせて **1SP ＝ 1時間** とする
