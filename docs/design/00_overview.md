## 要件定義書からの変更点（v1.2・メンターレビュー反映）

### ① Mustの絞り込み
コアバリュー「急な欠勤でも、講師どうしがサイト上で代講者を見つけて確定できる」に直結しないものを下げた。

| 対象 | 変更前 | 変更後 | 代わりの対応 |
|---|---|---|---|
| F-05 コマの定義 | Must | Could | コマは固定データ（Seeder）で用意し、管理画面は作らない |
| US-15 / F-03 講師の作成・無効化 | Must | Should | 初期の講師アカウントは Seeder で作成 |
| F-19 応募時の依頼者へのメール | Must | Should | 確定時のメール（当事者・スタッフ宛）は Must のまま |
| US-04 科目・学年の入力 | Must | Should | 引き継ぎメモは US-03 に含めて Must のまま |

結果：Mustのユーザーストーリー 14個 → 12個、Mustの機能 15個 → 13個

### ② 確定後に代講者が行けなくなった場合
今回は対象外（Won't）とする。運用上は、代講者が担当者になったシフトから改めて代講依頼を出すことで対応できる。

### ③ 数値の確定
| 項目 | v1.1 | v1.2 |
|---|---|---|
| 未確定依頼のスタッフ通知 | 授業開始の一定時間前 | 授業当日の12:00時点で未確定の、当日分の依頼をまとめて通知 |
| 成功の基準（確定までの時間） | 現状より短くなる | 現状（数時間）から、依頼作成〜確定の中央値を1時間以内にする |

## 設計方針
- 画面は Blade + Tailwind CSS（スマートフォン優先）。講師画面は 393px 幅を基準に設計
- 状態を変える操作（依頼・応募・確定・取り消し）とシフト表のデータ取得は JSON API として設計し、画面から呼び出す（認証は Sanctum のセッション認証）
- 確定処理はトランザクション＋行ロックで二重確定・二重シフトを防ぐ
- メールはキュー（database ドライバ）で非同期送信、定期処理は Laravel スケジューラで実行
